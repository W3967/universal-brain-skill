# 通用 AI 大脑方案

> 所有主流大模型共用同一份记忆，靠的不是给每个模型、每个应用单独做一套对接，而是把大脑这一侧定成一套稳定的标准接口：**私有仓库是唯一事实源，读取顺序、文件格式、快照包、验收办法全部写死、保持不变。** 谁想接进来，照着接口接；接口不为任何一方单独改。

> 接口版本：v3.0（草案）。相对 v2.0 冻结版的改动：核心文件分区所有权 —— 每个文件一个 owner（默认主写者），主写者任归属协调者；其余规矩不变。

| 私有仓库唯一事实源 | 按能力分档 | 验收才算接通 | 不绑任何应用 |
|---|---|---|---|

**一句话结论**：不重做大脑。仓库、数据、分级和同步节奏全部沿用已经跑起来的那一套，只做一件事 —— 把「怎么接进来」从各家各试，变成一套对所有接入方都一样的规矩。

---

## 一、本方案定的是什么

**只管大脑这一侧。** 仓库结构、读取协议、快照包格式、分档规则、回写与冲突规则、验收门槛。任何具体应用内部怎么做，不在本方案范围内。

**按能力分档，不按名字分档。** 接入方能直读仓库、能同步本地副本、能导入文件、还是只能粘贴，决定它进哪一档。明天出一家新模型，先测能力、再入档，不用为它新写一套办法。

**验收是正式门槛。** 读到文件不等于接通。接入方要按固定题库答对五类问题，才记为已接通；答错先查档位与投递方式，查不出就降档。

**接口稳定承诺。** 接口一旦定稿，变更要升版本号并提前说明，不悄悄改结构。已经接进来的各方，不会因为大脑改了格式而突然读不了。

---

## 二、三个前提

不满足这三条，这套东西会变成负担而不是工具。

1. **私有仓库是唯一事实源。** 必须 Private。L3 内容只存本地、永不进仓 —— 私有仓库也是服务器，不在这台机器上。
2. **分区所有权。** 每个文件只有一个 owner（默认主写者）；owner 写自己那块，对别人的块只读或走提议。
3. **不做双向自动合并。** 任何「两边自动对齐」的工具或功能都不在方案内，谁提议都先停下来问用户。

---

## 三、仓库就是接口

接入方不需要任何私有协议。**接口就是这个私有仓库本身**：固定的目录、固定的文件职责、固定的头信息。第一次接入的模型或工具，打开仓库根目录的接入说明就能开工，不用任何人再口头交代一遍。

```
universal-brain/
  README.md          接入说明：读取顺序、分档规则、红线
  index.json         全仓索引：路径、级别、摘要、标签、更新时间
  MEMORY.md          长期记忆核心版（L1，上限约 1200 字）
  answer-key.md      验收答案键（L2，不进快照、不随文档分发）
  profile.md         本人档案：称呼、身份、说话与回复偏好（L2）
  preferences.md     喜好、禁忌与已确认的长期约定（L2）
  tasks.md           跨接入方共享的任务与承诺清单（L2）
  projects/
    project-a.md     项目页（现状以代码与此页为准）
    project-b.md     项目页
    _template.md     新项目建档模板
  people/
    INDEX.md         人物索引，一人一页，只写已确认事实（L2）
  chats-opt-in/      仅用户逐条选定的聊天记录（默认空，L2）
  encrypted/         预留：L3 不在此
  _interface/        接口定义文件：非记忆内容，不进 index.json
    GRADING.md       分级矩阵
    ACCEPTANCE.md    验收判据
    COUNTING.md      文件清单与口径表
```

### 文件头信息规范

每个 Markdown 文件必备：

```yaml
---
level: L1            # 级别定义见 _interface/GRADING.md；L3 不入仓
owner: main-writer    # 占位写法：建大脑时换成主写者的名字；见第六节「分区所有权」
updated: 2026-01-01
source: manual       # 写入来源
tags: [记忆, 偏好]
---
```

正文只写已确认的事实，不写推测；同一事实只在一处维护，其他文件用引用指过去，不复制第二个版本。

### 索引规则

- 索引由同步工具在每次推送时**自动重建，禁止手工维护**。
- 没有一句摘要的新文件，同步工具拒绝推送并提醒补全。
- 新文件进仓只有一条路：先补头信息、再进索引、随每日批次推送。任何接入方不得绕过索引直接往仓库里塞文件。
- **唯一例外是接口定义文件**（`_interface/` 下三个文件）：它们入仓但不进 `index.json`，以免接入方按三级顺序读取时把接口定义误当成大脑记忆。

## 四、读取顺序与快照包

能直读仓库的，按固定顺序读；够不着仓库的，拿快照包。两者读到的是同一份内容、同一个版本，不是两套数据。**快照包是大脑主动生成的导出物，不是接入方自己拼凑的摘抄。**

### 三级读取顺序

| 层级 | 读什么 | 何时读 |
|---|---|---|
| 第 0 级 | `README.md` + `index.json` | 每次接入必读，先确认结构、版本与权限 |
| 第 1 级 | `profile.md` + `MEMORY.md` | 每次会话开始读，保证称呼、偏好与核心记忆一致 |
| 第 2 级 | 索引命中的具体文件 | 按任务需要读，例如聊到某项目时才读对应项目页 |

### 快照包最小格式

```
快照包/
  brain-memory.md      核心记忆合并版：MEMORY + profile / preferences 节选
  brain-manifest.json  清单：版本守门只看它，不靠猜
  brain-reference/     参考区：默认带两个项目页 + 人物索引
    projects-project-a.md
    projects-project-b.md
    people-INDEX.md
```

参考区只供被问到时查，不进每轮对话。默认范围就是两个项目页加人物索引，扩大范围要单独定，不默认带日志等未提炼原料。

### 清单必备字段

| 字段 | 作用 |
|---|---|
| `version` | 快照格式版本，与接口版本号对应；格式变了它先变 |
| `generated_at` | 生成时间，接入方据此判断手里这份有多旧 |
| `source_commit` | 生成时对应的仓库提交，出问题能定位到哪一版大脑 |
| `core_chars` | 核心记忆字数，超上限时生成直接失败，不出包 |
| `files[]` | 包内每个文件的路径、级别与摘要，与仓库索引同源生成 |

### 生成与投递分离

- **生成**是内部整理，每日随同步自动进行，**不需要授权**，但必须先过脱敏拦截。
- **投递**是外发，按接入方档位授权一次，每次投递前展示包摘要供确认。
- 白名单是一次性预授权：生成快照时不再逐次授权，只在投递时按接收方核对该方档位允许的范围。

快照只含分级矩阵白名单内的文件：核心为 L1 的 `MEMORY.md`，另加经授权的 L2 节选；`answer-key.md` 与 L3 永不进快照，`chats-opt-in/` 默认不进快照。

## 五、按能力分档

档位描述的是「这个接入方能做到什么」，不是「它是哪家产品」。同一家产品换了客户端、换了版本，能力变了就换档，大脑文件一行不动。**每档的读写权限在入档时定死，不口头放宽。**

| 档位 | 怎么读到大脑 | 覆盖范围 | 权限与限制 |
|---|---|---|---|
| **主写者档** | 经仓库授权按协议直读全仓；无日常操作，推送前确认即可 | 全仓 | 默认拥有全部核心文件；仍是做归并、重建索引与归属协调的唯一一档 |
| **直连只读档** | 接入方自己经连接器或仓库读取入口，按三级顺序读；先在接入方那侧完成一次授权 | 全仓（受授权约束） | 不拥有的文件只读，意见以提议形式交回；拥有指定文件时，可直改自己那块 |
| **本地副本档** | 接入方所在设备上存一份快照包副本，离线读副本；更新时按提示确认一次 | 快照包全部文件 | 只读副本。副本永远以大脑为准，不反向覆盖仓库 |
| **文件导入档** | 把快照包文件导入接入方的会话或知识库；每次更新重新导入新包，旧包作废 | 快照包全部文件（每次需重投） | 只读快照。读到的是生成那一刻的版本，新旧以清单时间为准 |
| **粘贴导入档** | 把核心记忆文本直接粘贴进对话；每次新会话都要重新粘贴一次 | 仅核心记忆，无参考区 | 最低保底档：不保证跨会话留存 |

档位定的是读取能力，写权限由 `owner` 字段另定：任何一档的接入方都可以拥有指定文件，写自己那块；不拥有的文件只读或走提议。主写者是默认 owner，不是唯一写者。

### 入档流程

1. **测能力**：先确认它够不够得着仓库、能不能导入文件、能不能跨会话留存，按结果定候选档位。
2. **按档投递**：直连的给读取入口与顺序，副本和导入的给快照包，粘贴的给核心记忆文本。
3. **过验收**：按固定题库答题，全对才算接通，答错走排查或降档。
4. **记实测**：把档位、日期、验收结果写进实测记录表。没记进表的，不算接通。

### 降档不是失败

直连不了就降到副本或快照，数据不迁移、格式不改。

档位低影响三件事：**新鲜度**（手里这份有多旧）、**操作次数**（是否每次都要重投）、**覆盖范围**（能看到仓库的哪一部分）。不影响的是：事实源唯一、格式统一、内容同源。

读到的是同一事实源的同一次快照，但**不是全量**；接入方必须知道自己的覆盖边界，边界之外不作臆断。

## 六、回写与冲突

通用化最容易出乱子的地方，是每个接入方都想往回写。规矩因此定死：**每个文件只有一个写入口（它的 owner），其余接入方对该文件是读者和提议者。** 写入口的数量随分区增加，但每块仍只有一个写者。

### 提议回路

1. 接入方在对话中发现新事实或错误，把内容整理成一条提议：事实本身、出处、建议写进哪个文件。
2. 提议经用户转交或接入方自己的回传通道，交到主写者手里，不直接落进仓库。
3. 主写者核对出处与现有记录：属实且无冲突的，并入当日批次；与现有事实冲突的，先报用户裁定，不自行取舍。
4. 归并结果随每日同步推送，提议方下次读取时自然看到，不需要单独通知。

### 分区所有权

核心文件按文件切块，不按文件内小节切：检查工具按文件跑，按小节切要解析标题，工具得大改。

- **登记**：每个文件的头信息带 `owner:` 字段（默认 `main-writer`）；`_interface/GRADING.md` 的「谁能写」列与头信息同源；索引（`index.json`）每条记入归属，接入方写之前先查索引。**命名**：分给不同接入方的块，`owner` 用该接入方的名字（如 `grok-bot`、`claude`），不用角色名或编号。主写者那块也一样，填主写者自己的名字；模板里的 `main-writer` 是占位写法，建大脑时换掉。
- **执行**：owner 写自己那块；别人的块只读或走提议回路。同步工具检查时要求每个文件都有 `owner:`，缺失直接失败（fail-closed）。
- **改归属、改级别、跨块合并**：走用户确认（大改走审核那条规矩）。
- **主写者改任归属协调者**：管归属表、管跨块合并、管验收；不再是唯一写者。
- **提交作者核对（CI 门）**：推送时，CI 比对本次改动文件的提交作者与各文件 `owner:` 是否一致，不一致拒绝合并。作者到接入方的映射关系各家自己定（例如按提交账号或邮箱映射），本方案只定「不一致就拦下」这条规矩。
- **既有大脑迁移**：v2.0 的大脑升级到 v3.0 时，给每个文件补 `owner:`（填主写者的名字；模板里的 `main-writer` 是占位写法），行为与 v2.0 完全一致，再按需把指定文件分出去。

### 冲突处理

| 冲突情形 | 处理 |
|---|---|
| 本地副本被改过，新版快照到达 | 以大脑为准覆盖。覆盖前先提示把本地改过的那份导出留底，留底完成或用户明确放弃后才覆盖，绝不一声不吭盖掉 |
| 两个接入方对同一事实说法不一致 | 各自只改自己拥有的文件；跨块的争议各自以提议交回，归属协调者（主写者）对照出处核实，核不实的报用户裁定 |
| 接入方读到的大脑版本过旧 | 以清单的生成时间与来源提交判断新旧；过旧的先更新投递，再继续答题或干活，不拿旧版本当现状 |
| 提议内容涉及 L3 或未选定的聊天记录 | 直接驳回，不入仓、不进快照。涉及隐私内容发给任何外部服务前，先征得用户同意 |

### 五条治理规矩

1. **分区单写**：每个文件只由它的 owner 修改；`MEMORY.md`、`profile.md`、`preferences.md` 默认归主写者。
2. **日志只追加**：按天追加、按来源分段，谁都不改别人的段落。
3. **写入带出处**：每条新记录注明时间与来源，写错可定位、可回滚。
4. **大改走审核**：删改既有事实先出对照说明，经用户确认后再合并；日常追加不逐条确认。
5. **L1 准入即外发准入**：能写进 L1 文件的，只能是可发给任意接入方的事实；写入前先分类，同步工具对 L1 文件做准入拦截，命中高敏类别直接拦下，不靠导出时脱敏补救。

> **防护放在内容进入的时候，而不是离开的时候。**

**红线：不做双向自动合并。**

## 七、接入验收

能打开文件、能复述目录，都不算接通。验收用固定题库，专挑「没读到大脑就答不出、读错版本也会答错」的内容。**五类全对，记入实测表；有一类错，就不算接通。**

| 类型 | 考什么 | 判对标准（结构描述） |
|---|---|---|
| **身份称呼** | 读没读到档案与核心记忆里的人物关系 | 能说出平时使用的称呼，并能说出一位家人的关键日期类事实（具体值以答案键为准） |
| **项目现状** | 读没读到项目页，且是不是最新版 | 能说出两个在册项目的当前版本号与状态（具体值以答案键为准，本文不写死会过期的事实） |
| **个人偏好** | 读没读到偏好文件与核心记忆里的生活偏好 | 能说出一项日常饮品偏好与一组语言约定（均以答案键为准） |
| **边界规矩** | 读没读到治理与安全边界，而不是只记住了事实 | 能说出三条边界规矩的类别：聊天记录的入仓条件、对外发送前确认的约定、核心文件分区归属 |
| **边界感知** | 知不知道自己读到了多少 | 能主动说出自己读的是哪一版、处在哪一档、覆盖范围到哪里、所涉文件归谁所有，并声明参考区之外的内容不作臆断 |

**第五类是重点。** 会答题不等于知道自己没看到什么。一个读了三份文件的接入方，如果不知道参考区之外还有东西，它会自信地谈论那些没读到的内容 —— 这比答错更危险。

本文只写判据结构，不写真实答案：真实答案存于仓库内的答案键（L2，不进快照、不随本文分发），判分时对照答案键，**判据与答案分离**。

### 投递未覆盖

这是唯一可以不算答错的情形，但必须**同时满足三条**：

1. 该题依赖的文件不在本次投递清单内
2. 清单已在答题前交给接入方
3. 结论记入实测表备注

**否则一律按答错处理。** 这条规矩防的是万能借口：任何答错都能归因于「你没给我那份文件」。三条硬性条件把它变成可核查的事实。

### 不过关时怎么办

1. **先查投递**：文件给全了没有、版本是不是最新、参考区在不在。缺项以投递清单为准，不以接入方口头解释为准。补齐后重测，不降档。
2. **再查档位**：投递没问题还答错，说明它留不住或跟不上这档的投递方式，降一档换投递方式重测。
3. **降到最低档仍不过**：记为暂不可接入，原因写进实测表，等能力变化后再测，不为它改大脑格式。

验收记录就是档位表 —— 它不是进度汇报，是接口的一部分：新接入方查表就知道每家验到哪一档、哪天验的。

## 八、安全边界

**分级红线以分级矩阵为准**：L3 不进仓、不进快照，任何 AI 不得要求、接收或转述；私钥绝不发给任何 AI。

- 仓库继续 Private；每个接入方单独授权、单独凭证，只给它那一档需要的最小权限，凭证设到期日、异常先吊销。
- 快照与同步推送前都过脱敏拦截，命中敏感模式直接拦下报警，绝不静默放行。
- 涉及隐私的信息发给任何外部检索或第三方服务之前，先征得用户同意；对外发送内容前先确认的既有习惯不变。

**要注意工具的边界**：脱敏拦截能拦可枚举的模式，拦不住「城市 + 学校 + 届别 + 年龄」这类组合起来才成立的可识别信息。所以工具管可枚举的一半，「写入前先分类」管另一半 —— **「工具没报警」不等于「可以推」**。

## 九、实施步骤

五张卡，全在大脑这一侧，不碰任何接入方的内部实现。

| 卡 | 做什么 | 验收标准 |
|---|---|---|
| **U-1 接入说明定稿** | 把仓库根目录 README 写成正式接入说明：读取顺序、五档定义、提议格式、红线，一页读完就能接 | 拿一个没接触过大脑的新会话照说明操作，能独立完成读取并进入验收环节，中途不需要口头补充 |
| **U-2 快照包生成** | 给同步工具加一步：每日检查时顺带生成快照包（核心合并版 + 参考区），生成前过脱敏拦截 | 生成的包解开后三件齐全；核心字数不超上限；故意放入假密钥时整包不出并报警 |
| **U-3 清单与版本守门** | 快照包带 `brain-manifest.json`（版本、生成时间、来源提交、字数、文件清单）；接口变更时先升版本号 | 拿一份旧包与新包对照，清单能一眼分出新旧与来源；版本号与接口版本对得上 |
| **U-4 验收题库定稿** | 把五类验收题写成固定题库与判据，真实答案只存仓库答案键，题库只引用键 | 判据无歧义、换人执行结论相同；复测已接通者时对照答案键判定五类是否全对，结果与既有实测记录一致才记通过 |
| **U-5 下一家实测** | 按入档流程接一家新的：测能力、定档、投递、验收、记表 | 实测表新增一行，档位与验收结果有据可查；不过关的按第 7 节路径处理并写明原因 |
| **U-6 分区所有权** | 给每个文件加 `owner:` 字段；检查工具校验归属声明并记入索引；验收加归属题 | 去掉某文件的 `owner:` 后检查失败；索引每条含 owner；读别人块正常，写别人块走提议 |

**执行顺序**：U-1 与 U-4 先行（说明和题库是其余三张卡的依据）；U-2、U-3 跟上；U-5 随时可插；U-6 在 U-1 之后做（归属表是接入说明的一部分）。

## 十、边界与不做的事

**本方案明确不做：**

- 不为任何单个应用写专属对接代码，不替任何应用定它内部怎么接
- 不做双向自动合并，不做实时同步，不做聊天记录回流
- 不把 L3 送进仓库或快照，不因接入方变多而放宽任何一条红线
- 不上向量检索：文件量小的时候，关键词加索引足够；等文件上百、关键词明显不够用时再单独评估

**任何应用想用大脑**，都在它自己那一侧照本接口对接，大脑不为它写专属代码、不为它改结构。
